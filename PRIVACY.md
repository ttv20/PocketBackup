# Pocket Backup Privacy Policy

Effective date: June 15, 2026

Pocket Backup is developed by @ttv20. For privacy questions or deletion
requests, contact:

ttv200+pocketbackupdelete@gmail.com

This policy explains what Pocket Backup accesses, stores, and sends.

## Summary

Pocket Backup backs up files from your Android device to a server that you
configure. @ttv20 does not receive your backed-up files, backup destination
details, SSH keys, passwords, or Tailscale account credentials.

Pocket Backup can send optional diagnostics and error reports to help debug
crashes, failed backups, and setup problems. F-Droid builds keep diagnostics off
unless you enable them. Other official builds may show diagnostics as enabled on
the first screen, and you can turn them off there or later in Settings.

## Data Stored On Your Device

Pocket Backup stores app configuration locally on your device, including:

- backup profile names, source paths, schedules, constraints, and log settings
- target names, server addresses, usernames, ports, remote paths, and trusted SSH
  host fingerprints
- backup logs and recent backup status
- selected Wi-Fi network names if you use Wi-Fi-specific backup constraints
- the app SSH public key and references to locally encrypted secrets
- Tailscale connection state if you choose to use Tailscale
- your diagnostics preference

Secrets such as private SSH keys, imported SSH key passphrases, and Tailscale
state are stored locally using Android Keystore-backed encryption. These secrets
are not sent to @ttv20.

## Backups

When you run a backup, Pocket Backup sends the selected files to the SSH server
or Tailscale destination that you configure. The transfer is part of the backup
feature and uses encrypted SSH transport.

@ttv20 does not operate your backup destination and does not receive, inspect, or
store your backed-up files.

## Optional Tailscale Use

Tailscale support is optional. If you use Tailscale, Pocket Backup connects to
Tailscale services for authentication, coordination, and private-network
connectivity. Pocket Backup may pass your chosen node name and Tailscale
authentication data to Tailscale as needed to connect.

Tailscale use is governed by Tailscale's own privacy practices:
https://tailscale.com/privacy-policy

LAN-only backups do not require Tailscale.

## Optional Diagnostics And Error Reporting

If diagnostics are enabled, Pocket Backup may send diagnostic events and crash
reports to services used by @ttv20, including an OpenObserve endpoint operated by
@ttv20 and, in builds configured for it, Measure.sh.

Measure.sh's privacy policy is available at:
https://measure.sh/privacy-policy

Diagnostics may include:

- app version, version code, build channel, and whether the build is an F-Droid
  or debug build
- Android version, SDK level, device manufacturer/model, and installation source
- a random Pocket Backup install ID used only for diagnostics
- event names, timestamps, feature area, result codes, failure categories, and
  sanitized exception type
- backup outcome metrics such as status, trigger type, route type, target mode,
  rsync exit code, file counts, byte counts, duration, and transfer speed
- crash metadata, stack trace hash, and sanitized stack trace
- profile and target IDs generated by the app

Diagnostics are used to understand app reliability, fix crashes, and improve
backup behavior across Android versions and devices. They are not used for ads,
marketing, or sale to data brokers.

Pocket Backup's diagnostics are designed not to send:

- backup file contents
- backup file names or local paths
- server addresses, remote paths, or usernames
- SSH private keys, passphrases, passwords, or Tailscale credentials
- rsync command output
- Wi-Fi network names

The diagnostics server is not intentionally configured to store normal HTTP
access logs for these requests. Network infrastructure still necessarily
processes IP addresses to deliver requests, but IP addresses are not part of the
diagnostic records @ttv20 intends to keep.

## Retention And Deletion

Local app data remains on your device until you delete it in the app, clear the
app's storage, or uninstall the app.

Diagnostic records are kept until they are no longer useful for debugging and
maintaining Pocket Backup. To request deletion of diagnostic records, email
ttv200+pocketbackupdelete@gmail.com and include your Pocket Backup diagnostics
install ID if available. Without the install ID, @ttv20 may not be able to find
the matching diagnostic records.

## Security

Pocket Backup uses encrypted transports for network features, including SSH for
backups and HTTPS for diagnostics. Local secrets are protected with Android
Keystore-backed encryption where supported by the device.

No method of storage or transmission is perfect, but Pocket Backup is designed
to avoid sending sensitive backup configuration or file details in diagnostics.

## Children

Pocket Backup is not directed to children.

## Changes

This policy may be updated when Pocket Backup's data practices change. The
effective date at the top of the policy will be updated when this happens.
